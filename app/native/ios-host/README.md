# PicknicHost — iOS dev shell

A minimal iOS app that embeds the Lynx runtime, loads the Picknic bundle from
the rspeedy dev server, and compiles in the `@vyui/camera` natives so
the real capture flow works on a physical iPhone (Lynx Go can't compile
native modules — this host is how M1/M2 get tested on device).

The project is generated by XcodeGen from `project.yml` — no Xcode-GUI setup.
The camera natives are compiled from the installed package
(`../../node_modules/@vyui/camera/ios`), which is all the package's
CocoaPods podspec does anyway. Both natives build clean against
Lynx 3.9.0 / Xcode 26 (verified against the iOS Simulator SDK).

## Prereqs (once)

- Full Xcode, signed in with any Apple ID (free personal team works).
- `brew install cocoapods xcodegen`
- iPhone with Developer Mode enabled (Settings → Privacy & Security).
- Phone and Mac on the same network as the dev server.

## Build

```sh
cd app/native/ios-host
xcodegen generate     # writes PicknicHost.xcodeproj from project.yml
pod install           # writes PicknicHost.xcworkspace
open PicknicHost.xcworkspace
```

Re-run `xcodegen generate` + `pod install` after editing `project.yml` or the
`Podfile`. Generated artifacts (xcodeproj, workspace, Pods/, Info.plist) are
gitignored — `project.yml`, `Podfile`, `Podfile.lock`, and `HostSources/` are
the sources of truth.

## Run on your iPhone

1. `pnpm dev` in `app/` — no URL to copy: a build phase writes the Mac's
   LAN IP into the app bundle (`DevServerHost.txt`), and at launch the app
   scans ports 3000–3010 on that host and loads the first dev server it finds.
   If the Mac changes networks, just rebuild. To pin an exact URL (e.g. a
   tunnel), set `manualBundleURL` at the top of
   `HostSources/ViewController.swift`.
2. In Xcode: PicknicHost scheme → your iPhone as destination.
3. Signing & Capabilities → set your team (change the bundle id if it
   collides).
4. Run.

### Release / TestFlight

Release builds don't touch the dev server: the "Embed Lynx bundle" build
phase runs `pnpm build` in `app/` (falling back to an existing
`dist/main.lynx.bundle` if pnpm isn't on the build PATH) and copies the
bundle into the .app, which `ViewController` loads directly (`#if DEBUG`
gates the dev-server discovery — `manualBundleURL` is Debug-only too).
A second phase strips the dev-only `NSAppTransportSecurity` and
`NSLocalNetworkUsageDescription` keys from the product's Info.plist, so
the shipped app has no ATS exemption and never prompts for local network.
Build with the scheme's Release config (Product → Archive already uses it);
if the phase can't produce the bundle it fails with instructions to run
`pnpm build` manually.

### Verify

- Picknic renders with the Comico display face (not a system-font fallback).
- Camera screen shows install status **installed** (not the missing-setup
  message).
- Shutter opens the real system camera; the captured photo — not the dev
  SAMPLE PHOTO — lands in the instax frame and uploads (API on port 8080 is
  reached via the same LAN host, see `src/api/config.ts`).
- M2 spike: a rendered `<camera-view>` fires `bindready` and
  `createCameraViewHandle('#camera').ping()` resolves `{ ok: true }`.

## Troubleshooting

- **Blank screen** — bundle fetch failed. Check `bundleURL` against the
  current `pnpm dev` output; confirm the phone can open it in Safari.
- **"engine version" mismatch on load** — the Lynx pod version and the
  rspeedy-produced bundle disagree; align the pod version in the Podfile
  with what the lynxjs.org guide pairs with the current `@lynx-js/rspeedy`.
- **Pod version resolution fails** — the pinned set has drifted; take the
  current versions from the lynxjs.org guide. Note PrimJS versions do not
  track Lynx's (Lynx 3.9.0 ↔ PrimJS 3.8.0-alpha.6), and CocoaPods requires
  prerelease versions to be pinned explicitly.
- **`-Werror` deprecation errors inside Lynx pods** — handled by the
  Podfile's post_install hook (rewrites per-file `-Werror` → `-Wno-error`);
  make sure `pod install` completed without a post-install error.
